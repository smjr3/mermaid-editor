# UI language

The editor's interface strings live in one catalogue and are looked up through a
typed accessor. There is no i18n framework.

## Why not a framework

Paraglide, the usual SvelteKit choice, wants a build plugin and — in its
SvelteKit integration — ownership of locale routing, so the locale lives in the
URL. This fork ships a single locale and builds a static site served from a fixed
subpath, so that machinery buys nothing and constrains the build and URL design.

The one thing a framework would genuinely buy — UI strings in one place instead
of scattered across components — is what `src/lib/i18n/messages.ts` provides on
its own, in one dependency-free file.

## Layout

| Path                        | Role                                                                        |
| --------------------------- | --------------------------------------------------------------------------- |
| `src/lib/i18n/messages.ts`  | The catalogue: `en` holds upstream's original wording, `ja` the translation |
| `src/lib/i18n/translate.ts` | Locale resolution and interpolation — pure, no `import.meta.env`            |
| `src/lib/i18n/index.ts`     | The app's `t(key)` and resolved `locale`, built from `translate.ts`         |
| `MERMAID_LOCALE`            | Build-time locale, `ja` by default; `en` restores upstream's wording        |

Keys are typed off the English catalogue, so a typo or a message deleted from the
catalogue is a compile error rather than a blank label at runtime. `t()` falls
back to English if a key is ever missing from another locale.

Both catalogues ship in the bundle. The locale is fixed at build time but read
through a runtime object lookup, so the unused one is not tree-shaken — a few
hundred bytes for the current key count, not worth complicating the accessor to
avoid.

## Adding or changing a string

1. Add the key to **both** `en` and `ja` in `messages.ts`, keeping each object
   alphabetical — eslint's `sort-keys` rule enforces that on objects this size.
2. Use `t('your.key')` in the component.
3. Run `pnpm check`. A key present in `ja` but missing from `en` is a type error.

## Migration status

Complete for everything the default build renders — 109 keys. Every component
that puts English on screen with the shipped feature flags now reads from the
catalogue: the toolbars and `Navbar`, `Preset`, `Actions`, `History`, `Editor`,
`Share`, `Privacy`, `MainMenu`, `DiagramDocumentationButton`,
`ExternalLinkWrapper`, `CopyButton`/`CopyInput`, the edit page, the error page,
the embed page, the `notify()`/`prompt()`/`alert()` call sites, and the unsafe-config
confirmation in `state.svelte.ts` (a security prompt, so it must be readable in the UI
language).

Deliberately left in English:

| What                                                                   | Why                                                                                                                  |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Sample diagram names (`Flowchart`, `Sequence`, …) in `Preset`          | They are keys into `@mermaid-js/examples`; a translation map would go stale silently on every upgrade                |
| `Mermaid Live Editor`, `Mermaid.js`, `Kroki`, `Powered by Mermaid`     | Product names and attribution                                                                                        |
| `AIPromptPopup`, `EnhancedEditsButton`, `migration/*`, `util/promos/*` | Behind feature flags this fork ships off, so they never render — translating them would only grow the upstream delta |
| The `Close` label in `components/ui/dialog`                            | Vendored shadcn-svelte, treated as third-party (screen-reader only)                                                  |

### The broken-URL diagram

`state.svelte.ts` renders a mermaid flowchart when a shared URL fails to parse.
It is one catalogue entry per locale (`error.urlParseFailedDiagram`) rather than
a set of fragments, because each locale has to be valid mermaid source on its
own.

This is the one place where the `en` catalogue is **not** upstream's wording.
Upstream ends the diagram with a `click` handler filing a bug against
`mermaid-js/mermaid-live-editor`; a fork must not send its users to upstream's
issue tracker for a link this deployment produced, so both locales point at the
deployment's administrator and the handler is gone.

### Interpolation

`t(key, params)` fills `{name}` placeholders:

```ts
t('external.unsupported', { domain }); // 「この図の種類は kroki.io では…」
```

A few lines in `translate.ts`, and it is what lets a translation put the value where
its own grammar wants it — concatenating at the call site fixes English word
order into every locale. `src/lib/i18n/i18n.test.ts` asserts that every locale
carries the same placeholders for a key, so dropping `{domain}` from a
translation fails the build rather than rendering a sentence with a hole in it.

The theme toggle predates it and stayed two keys
(`toolbar.switchToLight`/`toolbar.switchToDark`), which reads better than
interpolating a theme name into a sentence.

Where a translation has to wrap a link or a `<code>` span, the message is split
into ordered fragments (`privacy.hostedIntro` / `privacy.githubPages` /
`privacy.hostedMid` / …) so each locale can space and order its own prose around
the same markup.

## Keeping the e2e suite language-independent

The suite reaches for UI text far more than for `data-testid`, so translating a
string breaks whatever selector names it. Two fixes are in use, chosen per case:

**A `data-testid` where the element has no useful accessible name.** `Card`
gained a `testID` prop, and `TID` gained `actionsCard` and `sampleDiagramsCard`,
so `toggleActions()` and `toggleSampleDiagrams()` click by id rather than by
title.

**The catalogue itself where the selector is an accessible name.** `getByRole`
selectors read better naming the thing they mean, so `tests/test.ts` exports its
own `t()` and the specs assert against it:

```ts
await page.getByRole('tab', { name: t('history.tabTimeline') }).click();
```

That `t()` is built from `$/i18n/translate` rather than re-exported from
`$/i18n`, and the reason is worth knowing before trying the tidier-looking
version: `$/i18n` imports `src/lib/util/env.ts`, which reads `import.meta.env`.
Playwright runs the specs in plain Node, where that does not exist, so importing
the app's accessor makes every spec in the file fail to load. `translate.ts` has
no such import, so the test side reuses the app's own locale resolution and
interpolation and only swaps the source of the variable, reading
`process.env.MERMAID_LOCALE`. (Each side used to carry its own copy, and the copies
drifted: the test side once lacked the fallback to English.)

## Remaining text-coupled selectors

None. Every selector that named a translated string now names its catalogue key,
so the suite passes under either `MERMAID_LOCALE`. Two of them are worth copying
when adding tests:

```ts
// Empty-state messages are two lines; assert on the first, so the check does not
// depend on how Playwright normalises the newline.
await expect(page.locator('#historyList')).toContainText(firstLine(t('history.emptySaved')));

// Node A of the troubleshooting diagram, read out of the catalogue entry.
const heading = /A\[([^\]]+)]/.exec(t('error.urlParseFailedDiagram'))?.[1];
```

The selectors that still name English text — `getByRole('button', { name:
'Sequence' })` and friends — name sample diagrams, which are deliberately not
translated.
